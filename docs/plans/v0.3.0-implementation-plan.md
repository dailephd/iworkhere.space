## 3. Goal, scope and exclusions

Establish the document utility family and deliver the five Priority A PDF workflows using browser-local processing and the browser-validation foundation proven in v0.2.0.

1. PDF → JPG / PNG.
2. Images → PDF.
3. Merge PDF.
4. Split PDF.
5. Compress PDF.

Excluded: OCR; PDF editing and annotations/editing UI; signing; password removal, entry, decryption or guessing; Office conversion, PDF → Word and Word → PDF; cloud storage; user accounts; server file processing, new file-processing APIs or queues; generic background jobs; a universal file-processing framework; lossy PDF compression; full-page rasterization as compression; drag-and-drop; ZIP/archive output and automatic bulk downloads; v0.4+ utilities. Do not reorder or reduce the five-tool scope.

## 4. Domain ownership and dependency decisions

Document-domain behavior belongs in `src/module/tool/document/`. Routing under `app` remains composition-only and server-rendered by default; tool UI is client-side. Reusable presentation has no tool/domain ownership, and generic `lib` helpers do not import module behavior.

A narrow document primitive may own PDF header/signature checks, source-size rules, page-count inspection, safe display-name formatting and bounded parser error classification. Tool operations, state, object URLs and lifecycle remain local unless repeated implementation proves a truly identical contract. Do not place PDF logic in the image domain or generalize ImageFile into a universal binary abstraction. Reuse existing image contracts only for actual JPEG/PNG sources.

| Responsibility | Frozen implementation |
| --- | --- |
| PDF parsing, geometry and rendering; independent PDF verification | `pdfjs-dist@6.4.299` |
| Merge, Split and Images → PDF only | `pdf-lib@1.17.1` |
| Lossless structural compression only | Project-owned QPDF WASM 12.4.2 |
| QPDF upstream commit | `4eba95899886e851cc41d76886483b347612f2a8` |
| Server file-processing boundary | NOT_REQUIRED |

No user PDF/image bytes may be uploaded to application servers. No new file-processing endpoint, server queue or server background processing is authorized. No new vendor SDK is authorized.

## 5. PDF.js runtime and asset contract

Load PDF.js at operation time. Use its native worker and version-matched same-origin assets. It parses local bytes, inspects page count/dimensions/rotation, renders PDF → image, and independently parses/renders pdf-lib and QPDF outputs.

Explicitly review the worker, CMaps, standard fonts and image-decoding WASM against the supported fixture/capability corpus. Ship only assets actually required by accepted fixtures/features; do not copy all optional assets. Do not execute embedded PDF JavaScript or introduce QuickJS/PDF scripting support. External actions, links, forms and attachments are not execution surfaces.

Maintain a runtime asset/checksum manifest and required third-party notices. Container validation must prove every required asset responds HTTP 200 with correct MIME. No CDN-hosted worker or runtime code.

## 7. Worker ownership and heavy loading

Keep three narrow boundaries: PDF.js native parser/render worker, pdf-lib mutation worker, and QPDF compression worker. Do not build a generic PDF worker engine.

pdf-lib runs in a short-lived emitted module Worker: create → process one operation → transfer resulting Uint8Array → terminate. Do not import pdf-lib into ordinary initial tool rendering or create a persistent global worker.

QPDF runs in a short-lived browser Worker: input Uint8Array → MEMFS/in-memory staging → one QPDF CLI operation → output Uint8Array → transfer → cleanup staged files → terminate. Bound stdout/stderr internally; map initialization, processing, timeout and verification failures into bounded application categories. Never expose raw QPDF stderr, pointers or parser diagnostics to UI/telemetry. No QPDF state survives completion.

Terminate operation workers on success, failure, timeout, cancellation, source replacement, Reset and unmount. Ignore stale-generation results; cancellation is not an error. Revoke operation-owned object URLs and release source/result allocations when their owner ends. Test initialization failure, operation failure, timeout/cancel, source replacement, cleanup and repeated independent operations. Concrete timeouts remain batch-local engineering values established through acceptance; they do not justify persistent workers or enlarged limits.

All heavy PDF dependencies, compression workers and WASM remain absent from cold initial `/`, `/discover` and every non-document tool route. Use operation-time dynamic imports and same-origin assets. Measure before/after in Batch 1 and final integration. Do not redesign registry/component loading unless implementation evidence proves the frozen strategy fails; then stop for planner resolution.

## 8. Input security, fidelity and privacy

Encrypted/password-protected PDFs are unsupported. Reject locally with a clear error. Do not request passwords, guess them, remove them or treat pdf-lib `ignoreEncryption` as decryption. No password/document information enters telemetry.

Malformed/corrupt input must fail safely. PDF repair is not advertised. A parser's ordinary supported path may recover mild damage, but heavily malformed input is not trustworthy and recovered output is not silently accepted. Preserve bounded status/warnings at the engine boundary. In particular, QPDF warning/exit-3 recovery can drop pages: do not translate it into automatic compression success. Fail unless required static semantics can be independently verified under the supported path. Preserve the original on failure.

For Merge, Split and Compression, preserve and verify applicable page count, requested order, dimensions, rotation, renderable visible content and extractable text where present. If a required declared semantic cannot safely be preserved, fail before exposing output.

No preservation promise covers digital signatures, cryptographic validity, document-level metadata, bookmarks/outlines, attachments, embedded JavaScript, complex interactive forms, accessibility structure/tags or arbitrary application-specific PDF extensions. Fidelity is static page semantics, not interactive execution or signature preservation. User guidance must state these boundaries without implying unsupported capabilities.

No filenames, MIME types, byte sizes, page counts/dimensions, selected ranges, output sizes, PDF text/metadata, File/Blob contents, document URLs, passwords or raw parser errors may enter telemetry. Successful events use only existing safe identity fields such as toolId/slug through the observability abstraction. Bounded failure categories are allowed only where the existing contract permits them; expected failures stay in local UI, not diagnostic dumps. Do not place document data in URL state, persistence or network requests.

Recoverable errors use the owning tool's inline accessible feedback, known processing stage and realistic next action. No global error framework or storage/observability redesign. All five operations remain browser-local.

## 10. Shared page-selection and ordered-input contracts

The pure parser accepts one-based expressions such as `1`, `1-3`, `1,3,5`, and `1-3,6,9-10`. Expand each range in ascending order and preserve the sequence requested by the user; do not globally reorder separately requested segments. Normalize duplicates or reject them consistently across both consumers, documenting and unit-testing the chosen policy. Invalid syntax and out-of-range numbers produce an inline error. Test boundaries, whitespace policy, malformed ranges, duplicates, sequence, empty selection and output caps.

Create a document-family-local ordered-file model containing stable local item ID, File, validated local metadata and order. Support add, remove and accessible move up/down; replacement only where the operation explicitly needs it. Pure domain-level transitions may be shared when identical. No site-wide file manager, drag/drop framework or universal processing abstraction. File/document metadata stays local.

## 11. Frozen tool behavior

### PDF → JPG / PNG

Use PDF.js for selected-page rendering. Provide explicit page selection with the shared parser and at most 20 output images per operation. PNG has no quality control. JPEG exposes the simple bounded quality control above; do not add knobs unsupported by browser canvas encoding. Honor 72/150/300 DPI and render bounds. Validate output MIME and dimensions with native browser image decoding. Show a bounded list of individual download links; no archive, automatic bulk download, OCR or text-extraction product feature.

### Images → PDF

Accept 1–20 JPEG/PNG images within 25 MiB aggregate, using existing image source validation where semantically correct. Order matters; provide accessible move up, move down and remove. One image becomes one page. PDF page dimensions equal the image's intrinsic pixel dimensions numerically in PDF points; preserve aspect ratio exactly. Verify PNG transparency through independent PDF.js rendering. No captions, margins, paper-size templates, layout editor, multiple images per page or cropping.

### Merge PDF

Accept 2–10 PDFs within 25 MiB aggregate and 100 aggregate pages. Provide accessible up/down/remove controls, no drag/drop. Produce one deterministic PDF, preserving input document order, each document's page order, dimensions, rotation and declared visible/text semantics. Validate independently with PDF.js before download.

### Split PDF

Accept one PDF. Provide explicit output groups, each using the shared page-selection parser; at most 20 groups. Examples: Group 1 `1-3`, Group 2 `4-6`, Group 3 `7,9`. Each group produces one independently verified PDF. Deterministic filenames identify group/range. No automatic ZIP or mass downloads.

### Compress PDF

Use only project-owned QPDF 12.4.2 and LOSSLESS_STRUCTURAL options equivalent to `--object-streams=generate --recompress-flate --compression-level=9`. No lossy image recompression or page rasterization.

If verified output bytes are smaller than input, show original size, compressed size, bytes saved, percentage saved and a download. If output bytes are equal or larger, discard the generated replacement, retain the original local source and show **NO REDUCTION ACHIEVED**. Do not offer a misleading compressed output. Successful rewrite alone is not compression; no reduction is a normal product outcome.

Measured structural corpus results included 42.187% reduction for text/vector, 0.302% for mixed content and 1.656% for 100 text pages; JPEG/PNG/already-optimized fixtures grew slightly. All structural sampled renders matched, with page geometry/rotation/text preserved. This evidence supports truthful outcomes, not guaranteed savings. Separate lossy tests visibly changed pixels and are deferred for all of v0.3.
