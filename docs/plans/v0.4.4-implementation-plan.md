## 6. Correctness and tool-journey contract

### Calculator

Keep the safe parser and existing basic arithmetic feature boundary. The
grammar is:

~~~text
expression = product (("+" | "-") product)*
product    = unary (("*" | "/") unary)*
unary      = ("+" | "-") unary | primary
primary    = number | "(" expression ")"
number     = digits ["." [digits]] | "." digits
~~~

Whitespace may separate tokens; it may not combine two numeric tokens.
Unary signs bind more tightly than multiplication/division. Repeated unary
signs follow that grammar. Binary operators of equal precedence associate
left to right. There is no implicit multiplication, exponent input, percent,
function evaluation or arbitrary precision.

Independent required examples: 2 * -3 = -6; 2 / -2 = -1; 1--2 = 3;
-(2+3) = -5; 2 * (-3) = -6; --2 = 2; +2 = 2; 2 + 3 * 4 = 14;
(2 + 3) * 4 = 20. Empty input, a bare decimal point, adjacent numbers,
2(3), 2 ** 3, trailing operators and mismatched parentheses are errors.
Division by zero and nonfinite results remain errors.

Preserve keyboard Enter/=, Clear, backspace, expression URL sharing and
query-redacted telemetry. Preserve the existing documented floating-point
display precision, normalize negative zero, and test very small/large finite
display values without promising exact arithmetic. Remove the published
workaround that tells visitors to expect the wrong negative-product result.

### Length and weight

Preserve supported units, immediate updates, negatives where currently
accepted, and the six-decimal display policy. Parse the entire trimmed
numeric input; reject blank, malformed and nonfinite values. Check conversion
results before formatting. A finite representable same-unit conversion must
not fail solely because an avoidable intermediate scaling step overflows.

Use a visible, accessible out-of-range message instead of Infinity, NaN or a
fabricated answer. Required boundaries include ordinary conversions, zero,
negative values, tiny values under the existing rounding rule, invalid text,
1e308 identity conversion, and a conversion whose real result exceeds the
finite number range. The guide must accurately distinguish rounding from
measurement accuracy.

### Durations

Preserve nonnegative H:MM durations, minutes 00–59, hours beyond 23, carry/
borrow and rejection of negative subtraction. Parsed hours, each total-minute
value and the computed result must be safe integers. Do not silently round
very large durations. Invalid operands use the existing field-validation
path; a valid-input addition exceeding the safe range returns an explicit
result-out-of-range error through the existing result contract.

Test 01:50 + 00:20 = 02:10; 50:00 + 50:00 = 100:00;
02:00 - 00:45 = 01:15; equality = 00:00; invalid minute syntax;
negative subtraction; maximum safely representable minute totals and the
first unsafe addition.

Use existing test owners and small known inputs:

- Images to PDF: verify image order, page count, dimensions and alpha handling.
- PDF to Image: verify chosen pages, rotation, DPI dimensions and format.

- Word counter: verify the stated Unicode/grapheme/line semantics, reset and limits.
- QR: decode the generated PNG independently to the exact original payload;

No new utility is authorized by a missing test. If a promised existing behavior
