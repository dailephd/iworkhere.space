## 1. Why this version exists

The publisher reported a Google AdSense site-review rejection labeled **Low value content** on 2026-10-18. Google asked for authentic, useful content/tools/services, ongoing curation and genuine user interest. This decision is an external account observation reported by the operator; the repository cannot independently establish Google's undisclosed page-level assessment or user-interest thresholds.

Google's [AdSense content and user experience guidance](https://support.google.com/adsense/answer/10015918) asks for original value, sufficient content to understand a site, clear navigation and a reason to visit or return. Google's [people-first content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) is an additional quality reference, not an AdSense scoring formula.

Current source evidence as inspected during planning:
- Eighteen registered utilities in seven populated categories, with 28 sitemap URLs including /privacy.
- Functional image/PDF workflows and server-rendered tool guides, including the F-03 guides.
- Homepage src/app/page.tsx has a generic short introduction and registry-derived catalog, not a distinctive task/use-case explanation.
- src/app/discover/page.tsx is primarily search/catalog navigation.
- src/app/category/[category]/page.tsx renders a short shared category description and links; lower-density categories offer little other guidance.
- The footer identifies dailephd LLC; there is no src/app/about or src/app/contact directory in the inspected baseline.
- The current source's technical validation does not prove Google approval, search indexing, visitor engagement or content originality.

Do not fabricate an AdSense requirement for a minimum number of articles, words, monthly sessions, backlinks or traffic. Do not assume Google rejects utility-only sites. Product value is demonstrated by the usable tools and original, accurate supporting material together.

## 3. Product outcomes and visitor journeys

Primary visitor outcomes:
1. A visitor can immediately choose an actual task (compress a PDF, export PDF pages, combine images to PDF, resize an image, change image format), understand the supported input and output, and reach the correct working tool without scrolling through an undifferentiated directory.
2. On each of the five featured utility pages, a visitor can inspect at least one **original, reproducible, implementation-verified** before/after example with meaningful numeric facts and limitations. Examples demonstrate the existing tool, not a simulated capability.
3. Visitors browsing a category can understand which registered tools solve which real needs and when to select one over another; low-density categories do not become thin keyword variants of the same generic catalog copy.
4. Visitors can verify the website's publisher/maintainer, contact or reporting route, file-processing practices and actual maintenance approach. No invented testimonials, traffic, customer counts, endorsements or achievements.
5. Operators have a bounded, factual way to track production releases, broken examples, feedback, indexing and actual user interest; no fake engagement and no ad-review promises.

Quality acceptance is based on correctness, originality, accessibility and demonstrated task success, not word count or how many new pages were created.

## 5. Five original demonstrations (required content contract)

The first version-wide content pack targets existing utilities:
- compress-pdf
- pdf-to-image
- images-to-pdf
- image-resizer
- image-converter

Each demonstration record must include:
- Unique example ID and exact registered tool ID.
- Visitor question/use case and why this tool is appropriate.
- Original asset source/provenance, author/license permission and public URL when an asset is exposed.
- Reproduction steps using controls the actual tool provides.
- Source format, size/dimensions/pages and exact measured output format, size/dimensions/pages where relevant.
- What changed, what must remain unchanged, and what this tool cannot guarantee.
- A test or independent verification record proving the stated results for the shipped source assets.
- Concise alt text, caption and, when needed, a nonimage text/table equivalent.
- Meaningful accessible links. Never download automatically or request a file upload merely to view an example.

Per-tool requirements:
- **compress-pdf**: an original static-page PDF and truthful outcome from the existing QPDF-backed lossless structural compression. Record source/output byte sizes and independent page-fidelity verification. If the example yields no smaller result, display that result transparently; do not stage a fictional reduction or promise all PDFs shrink.
- **pdf-to-image**: a small original multipage PDF with distinctive text/visual content; show selected page(s), requested DPI, output PNG/JPG choice, raster dimensions, rotation behavior and the existing 20-image/canvas limits. Do not suggest unsupported ZIP/all-pages behavior.
- **images-to-pdf**: small original JPEG/PNG inputs and an actual produced PDF; preserve shown order, one-image-per-page semantics, pixel-to-point page-sizing rule and transparency/metadata caveats. Do not claim paper-size or crop controls that are absent.
- **image-resizer**: original image showing visible dimensions (for example 800 × 600 -> 400 × 300 with aspect ratio preserved); verify dimensions and output format, explain that upscaling cannot recover detail. Never claim smaller bytes as guaranteed.
- **image-converter**: same original source image converted through supported JPEG/PNG/WebP options; explain format/dimension preservation, transparency/JPEG white background and lossy-vs-lossless distinctions. State real source/output sizes if displayed.

Prefer a small number of transparent, high-quality examples to large galleries. Sample assets are optional downloads and must not require a remote third-party service. Use synthetic graphics and documents specifically created for this project, not borrowed branded images, copyrighted PDF screenshots or user files. All links must resolve. Ensure public asset weight and initial page performance stay reasonable; use thumbnails/links instead of eagerly downloading every full sample.

Do not author values before generating and verifying the actual assets. There is no approved precomputed benchmark number, percentage reduction, file-size claim or visual comparison in this planning document.
