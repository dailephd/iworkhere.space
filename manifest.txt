0. REQUIRED READING / AUTHORITY / STOP RULE
------------------------------------------------------------
BEFORE every coding-agent task that reads or changes this repository:
  A. Read the root AGENTS.md and CLAUDE.md (the tracked names are .md, NOT agents.txt/claude.txt).
  B. Read this complete manifest.txt alongside them, before choosing an edit destination.
  C. If local agents.txt or claude.txt exist, read them too as supplemental task guidance; do not assume they are tracked or more authoritative.
  D. Read docs/architecture.md, docs/doc_index.md, and the exact applicable domain spec/plan as needed.
  E. Verify Git branch, commit, status and current tracked paths. This manifest is a snapshot; current Git/source wins for facts.
  F. Use my-dev-kit against the current relevant source roots: search -> lookup -> bounded slice when useful -> exact source -> continuation/local dependencies. Full source/test reads only as a documented last resort.
  G. State the existing owner, extension point, closest tests, allowed edit paths and excluded paths before editing.
  H. Stop and report an exact conflict if current Git, AGENTS.md, CLAUDE.md, specs and this manifest cannot be reconciled. Do not guess or create a parallel owner.

Authority is field-specific: user-approved scope + docs/ROADMAP.md govern planned work; current source and tests govern implemented behavior; docs/architecture.md and current contracts govern boundaries; docs/DESIGN.md governs visual changes; docs/TESTING.md and CI_CD.md govern validation; docs/project-status.md and release/deployment evidence govern current lifecycle. Frozen version plans govern their approved batches, not future features. This manifest maps directory roles, not the semantics of every API.

For every coding change, report: path owner, why it belongs there, my-dev-kit evidence, relevant existing pattern, tests, docs, diff, any newly created directory with justification, and whether the file/folder inventory changed. A directory is NOT a feature-version, experiment, or coding-agent workspace.

5. CHANGING OR CREATING A FILE — MANDATORY DECISION GATE
------------------------------------------------------------
1. Identify requested behavior and exact authorized version/batch.
2. Inspect current Git tree and relevant AGENTS.md + CLAUDE.md + manifest.txt + architecture/spec.
3. Retrieve existing owner/contracts/tests with my-dev-kit. Filename similarity alone is insufficient.
4. Select an existing directory/symbol. If creating a new folder, explain why no listed owner works and obtain planner authorization for that boundary.
5. Maintain clear separation: domain algorithm and tool-local React UI in src/module/tool/<category>/; shared pure generic helper ONLY in src/lib after evidence; generic reusable presentation in src/component; app only routing/composition.
6. Registration: extend src/module/tool/registry.ts explicitly; category identity comes ONLY from category.ts, metadata queries from metadata.ts, guides from guide.ts. Do not create independent arrays/registries/tool pages.
7. Preserve browser-only data privacy; no user contents in URL sharing, telemetry, storage or server unless explicitly authorized and documented. New security-sensitive utilities default to no persistence/query sharing.
8. Extend corresponding tests and only relevant specs. Test negative and boundary behavior and adjacent regressions. For visible UI, preserve browser, accessibility, desktop/mobile and styling evidence.
9. Run required validation and inspect Git diff for wrong-layer edits, unintended file moves, generated artifacts and changed docs. Return an exact structured report.
10. No release, tag, publish, deploy, branch deletion or irreversible cleanup without explicit authorization.
